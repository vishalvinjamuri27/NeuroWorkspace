# NeuroWorkspace v0.1.0-alpha.1

This is the first public-alpha candidate. It is intended for supervised and
small-cohort evaluation by EEG researchers, BCI developers, and neurotechnology
teams. No remote tag or release was created during preparation.

## What works

- Open a shared, attributed public EEG sample without an account.
- Create a hosted OIDC account/session, workspace, and project.
- Upload supported files, observe durable ingestion, and return to the recording.
- Navigate bounded waveform windows, zoom, pan, jump, and toggle channels.
- Review source events, safe metadata, transparent non-diagnostic QC suggestions,
  manual bad-channel decisions, and attributed annotations.
- Create an average-reference derived version and export annotations, QC, or
  provenance.
- Submit privacy-bounded feedback with optional contact permission.
- Measure activation, upload success, meaningful viewer use, annotation/QC/export,
  later-session reopen, safe format/size distribution, and multi-recording behavior.

## Supported formats and tested data

- EDF/EDF+: PhysioNet Sleep-EDF Expanded 1.0.0.
- BioSemi BDF: HBN-EEG challenge R1 public BDF derivative.
- BrainVision and BIDS foundation: OpenNeuro ds006547 v1.0.0.
- EEGLAB: OpenNeuro ds004362 v1.0.0.
- FIF: official MNE testing-data fixture.
- configured CSV/TSV: explicit schema wizard and generated fixture.

The public in-product sample is the pinned OpenNeuro ds004362 EEGLAB recording,
dataset-declared CC0, DOI 10.18112/openneuro.ds004362.v1.0.0. Compatibility with
every exporter/version is not implied.

## Known limitations

- Research/engineering use only; not a medical device, diagnostic system, or
  clinical interpretation tool.
- Not HIPAA compliant. Do not upload identifiable or regulated health information
  to a public alpha.
- The public sample is shared and read-only. Import permitted own data to annotate,
  mark bad channels, process, or export.
- Hosted identity needs a configured OIDC provider; no enterprise SSO/SCIM.
- Canonical Zarr requires a shared durable POSIX volume across API/worker replicas;
  it is not yet object-native.
- No live streaming, new modalities, ML/AI, diagnostic behavior, mobile app, or
  elaborate collaboration.
- Format parsers may encounter producer-specific files not represented in the
  pinned corpus. Use the safe error reference when reporting one.
- Browser heap/long-session stability has not been quantitatively measured across
  participant hardware.
- Docker/Compose boot and restart-persistence are **not validated on the
  preparation host** because Docker was unavailable. A deployment must pass the
  documented container gate before public invitations.
- No hosted demo URL or public repository remote was configured in this checkout.

## Privacy and bug reporting

Product analytics exclude samples, filenames, subject/patient fields, source
headers, annotation text, clinical notes, and uploaded files. Feedback does not
attach them automatically. Review [PRODUCT_ANALYTICS.md](../PRODUCT_ANALYTICS.md)
and [PUBLIC_ALPHA_SECURITY_REVIEW.md](../PUBLIC_ALPHA_SECURITY_REVIEW.md).

Use the in-app **Send feedback** action for product problems. Include only the safe
error reference, format category, broad size, and reproduction steps. Do not attach
real EEG or identifying metadata. Report suspected vulnerabilities privately
through [SECURITY.md](../../SECURITY.md), not a public issue.

## Operator release gate

Follow [PUBLIC_ALPHA_DEPLOYMENT.md](../PUBLIC_ALPHA_DEPLOYMENT.md), run the
container/restart procedure, configure the public repository URL and privacy/legal
notices, verify backups/monitoring/on-call ownership, then invite only the first
five observed testers. Do not broaden distribution from this draft alone.
